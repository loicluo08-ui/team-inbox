## 一、要解决的问题（为什么需要回流）

当前内容链是**单向流**：录课/v18册蒸馏→切片/正件→装配→打印→（验收链）。学生真实使用中产生的错误信号（哪道题错、哪个知识点卡、哪个讲法没接住）**没有回流入口**，导致：

1. 易错卡只能从"录课原话强调+UP主经验"先验生成，无后验数据校准——57条#18（经典例题+易错题齐）与#9（有错必须被抓出来改掉）在"学生真实错误"维度上是断链的
2. 考点底表权重（C1频次实证）只有先验频次，无本地错误率修正——高频≠易错，本地错误率是稀缺信号
3. 讲法有效性无反馈：切片卡"讲法照录"是否真的让零基础听懂（57条#1），只有Alex侧人工复验一道闸，无规模信号

## 二、机制总设计：三条回流路径（MECE）

```
错题源（学生侧）→ 采集分诊台 → ①正件勘误流 ──→ 两道闸修复链（现有制度直接承接）
                │            ├→ ②易错卡扩容流 → 新卡/改卡走切片卡同规格（S8+首件制）
                │            └→ ③考点权重流 → C1底表权重修正表（只修权重不改内容）
                └── 全程：claim登记+冲突申报+N轮复扫铁律不变
```

**路径①正件勘误流**（纠错回正件）：
- 触发：错误根因=正件内容错误（答案错/表述误导/链接失效）
- 流向：错题分诊单→伤单分诊（真修/豁免两栏制·沿用§一铁律）→两道闸→N轮复扫
- 验收：复用现行验收链（机检双跑exit0+冲突标记0+A4锚点），错题来源行号留痕

**路径②易错卡扩容流**（错误→新卡）：
- 触发：错误根因=讲法没接住/常见误判（内容无错但学生系统性卡壳）
- 流向：分诊台→新易错卡工单（四元：症状/错因/维持机制/钉死）→按件首件制候验→回流装配
- 规格：与现行易错卡四元完全同构；卡源=真实错误描述（学生原话/作业照录），宁缺毋编——**一条真实错误一条卡，不足额不凑数**

**路径③考点权重流**（信号→底表）：
- 触发：同类错误在多个学生重复出现（≥N次，N初值=3，候定）
- 流向：错误计数表→C1底表旁挂"本地错误率"列→影响后续节次/卡片的排产优先级
- 红线：**权重只影响排产排序，不直接改正件**——防止小样本噪音驱动内容变更（与#40"逐条来不打包"精神一致）

## 三、采集分诊台设计（中枢）

- **载体**：仓内`错题回流_分诊台账.md`（初期纯人工登记，MVP）
- **字段（七元）**：编号｜日期｜科目｜错误描述（学生原话照录）｜涉及件位（canonical路径+行号/节锚）｜初判根因（①/②/③）｜状态（待分诊/分流中/已闭合/豁免登记）
- **分诊权**：初判由认领席执行，**改判权在Alex**（沿用"冲突我摆你拍板"协作四法）
- **铁律继承**：只判不改（分诊不直接修件）；每错误条独立编号不打包；全程留痕进制作日志

## 五、风险与红线

1. **宁缺毋编红线**：禁止"推测学生可能错什么"式预填——回流台账只收真实错误，空台账合法
2. **同文件双工种**：路径②改卡与路径①修复件可能撞同文件——沿用§十一-2顺序铁律（净面/修复先行push，扩容在后rebase）
3. **隐私边界**：学生侧原始信息（姓名/试卷可识别信息）不入仓——只留"错误描述+题干必要部分"
4. **勿过度建设**：本方案MVP零代码；远期自动化候显式令，不预铺
